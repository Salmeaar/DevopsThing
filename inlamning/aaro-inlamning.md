Kursen har varit extremt intressant att följa ända sen från första committen i m1. 
M1 var en ljuvlig mjuk start till kursen då man endast checkade till att alla faktiskt hade en github account och att ingen hade lyckats dra sig till en tredje årets kurs utan en och att ingen fick överraskande strul med att laga till en ny repo från templaten.
M2 var en väldigt bra riktgivare till vad kursen kommer och var då den säkerställer pull request reviewing processen och övade git konflikt resolvande.
M3 var en nice catch up på vad och hur docker fungerar inom infrastrukturen och hur den säkerställer fungerandet applikationen fungerar oberoende vem runnar den på vilken maskin.
M4 lär oss att testerna är alldrig är 100% säkra och måste alltid uppdateras och förbättras och bra att dubbelchecka allti nu och då.
M5 börjar på CI delen och den kräver att vissa checks man bestämt tidigare MÅSTE gå igenom för att branchen skulle kunna mergas till produktion. Detta steg säkerställer att inga klara problem med tester som funnits länge kan mergas.
M6 lagar docker imagerna publica och bygger upp basen för fullt automatiska driftsättandet med hjälp av dem.
M7 lagar till manuellt en VM instance på pouta och lär oss manuellt driftsättande och hur man navigerar en server genom terminalen med SSH nycklar och dubbelcheckar URL:ar med curl.
M8 fixar automatiseringen av M7 med hjälp av terraform, vilket är en IaC (Infrastucture as Code) verktyg som fungerar som en bottenplan åt appliaktioner så de kan hostas på olika molntjänster, och möjliggör att man i framtiden kan automatisera uppdateringen vid varje merge.
M9 är precis automatiseringen av att uppdatera produktion applikationen real time då en version uppdatering mergas intill main branchen i github utan att ingen behöver manuellt göra det.
Utan automation är det flera steg som kan gå sönder. Änklaste att peka ut är endera M5 eller M9, då M5 snabbar till code reviews och möjliggör undvikande av de vanligaste buggar medan M9 automatiserar bort människo faktoren i produkt uppdateringen då ingen personligen behöver logga in till VM:en och ha en liten risk att de imisstag skulle läcka någon SSH nyckel eller andra secrets överhuvudtaget då allting kör lokalt på VM:n. Viktigare av dessa 2 tycker jag är kanske M5 då code review kan bli en stor arbetsområde snabbt ifall ingenting kan automatiseras och då är det änklare för misstag att hända, medan M9 kan man i princip göra bara lite mer sällan så mängen gånger secrets används minskas.
